# OIDC 组织编码与部门层级同步

## 目标

超级楚楚通过 `OIDC_PROVIDER_TYPE=cnnp` 读取认证中心 UserInfo 中的公司、部门编码，按稳定编码维护公司主体、部门树及用户主部门，同时允许管理员维护独立的本地展示名称。

## 数据与同步规则

- `entity_code` 唯一对应公司主体根节点，`entity_short_name` 保存为主体 OIDC 名称。
- `dept_code` 格式为 `BM<偶数位数字>` 或 `<前缀>-BM<偶数位数字>`，数字每两位一级。例如 `BM2203` 的父链为 `BM22 → BM2203`，`JXI-BM460503` 的父链为 `JXI-BM46 → JXI-BM4605 → JXI-BM460503`。
- 深层部门先登录时自动创建缺失父级；无名称的占位节点使用编码展示，父级人员登录后补齐其 OIDC 名称。
- 部门展示顺序为：本地名称、OIDC 名称、部门编码、公司编码。
- OIDC 同步只更新 OIDC 名称，不覆盖管理员本地名称；编码和父子关系不可通过管理接口修改。
- 唯一同名存量节点仅在预期父级内、尚未绑定编码时自动认领，禁止跨主体按名称猜测。
- CNNP 用户每次登录同步主部门；仅保留新主体内的兼职部门。
- 公司或部门编码缺失、非法时，用户同步到 `OIDC_DEFAULT_DEPARTMENT`。
- `standard` 适配器及普通本地部门行为保持不变。

## 验收 Checklist

- [x] `cnnp` 正确映射 `entity_code`、`entity_short_name`、`dept_code`、`dept_name`。
- [x] 三级部门首次登录能生成主体、父级占位节点和完整 closure 路径。
- [x] 父级后登录只补齐对应 OIDC 名称，本地名称保持不变。
- [x] 重复或并发登录不产生重复编码节点。
- [x] 老用户主部门随 OIDC 变化，跨主体兼职关系被停用。
- [x] 部门 API 同时返回有效名称、本地名称、OIDC 名称和编码。
- [x] 管理界面可清除本地名称覆盖，但不能移动 OIDC 节点。
- [x] standard OIDC、普通登录、组织权限与本地部门 CRUD 回归通过。
