# 自定义角色权限矩阵

## 目标

在保留现有 `superadmin`、`admin`、`user` 默认行为的基础上，引入可持久化的全局自定义角色与“资源 × 动作”权限矩阵。权限决定用户能执行的动作，部门、创建者和 `share_config` 继续决定动作可作用的数据范围。

## 验收标准

- 超级管理员可创建、编辑和删除未被使用的自定义角色，并为用户分配单一角色。
- `superadmin` 始终拥有全部权限且不可编辑；`admin`、`user` 不可删除或改 key，但可调整权限。
- 登录和当前用户接口返回角色名称及权限列表，前端菜单、页签和按钮按权限展示。
- 后端所有管理能力以权限检查为最终边界，API Key 每次请求使用绑定用户的当前角色权限。
- 权限不能绕过部门、资源创建者或共享范围；按 ID 操作知识库时仍需通过资源级授权。
- 非法角色、未知权限、删除在用角色和越权操作返回明确的 4xx 响应。

## 角色数据权限扩展

在功能权限之外，角色增加模型、内置 Tool 和 MCP 服务的资源访问范围。每组资源支持全部、指定、无权限三态；受限模型可分别为 `chat`、`embedding`、`rerank` 指定角色默认模型。

资源权限必须同时作用于选择目录、配置保存和实际运行。共享 Agent、子智能体、恢复任务、JWT/API Key 及 Worker 均按实际用户当前角色复验；Skill 的直接与传递依赖不得绕过 Tool/MCP 白名单。历史角色升级保持全部资源兼容，新建自定义角色默认无资源权限，超级管理员继续拥有不可修改的全资源旁路。

`knowledge-base` Skill 的知识库工具不属于角色 Tool 数据权限配置项，不在数据权限目录展示，也不参与 Tool 白名单校验；其访问范围继续由知识库权限、部门/共享规则和会话启用的知识库共同决定。
